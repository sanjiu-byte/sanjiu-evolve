# sanjiu-evolve · 三九·创作进化

版本：0.1.0。使用模拟与验证边界见 [检查报告](CHECKS.md)。

从真实项目与反馈中积累方法，帮助 AI 理解客户需求，写出更符合项目的脚本与提示词。

第一版采用 Sanjiu 已在实际工作中使用、持续修正的创作方法。先把这一套用好，暂不拆成“个人版”和“通用版”。这些是可调整的工作默认，不是所有创作者都必须遵守的标准；具体客户要求和本次明确决定优先。

## 最简单的使用方式

把这个文件夹放在本机，让能读取本地文件的 AI 执行下面这段话，将路径替换成实际位置：

> 请读取「sanjiu-evolve/SKILL.md」，本项目启用这套创作与反馈流程。我授权你在本机维护本项目的经验与任务接续记录：优先使用已有权威记录，没有时使用项目内不入仓的本地记录。先修好当前成果，再沉淀明确可复用的纠正；不要把单次要求变成长期默认。我说“不记”时，不为这条反馈保存正文、摘要或日志。不因这段授权上传或分享项目资料。当前要做的是：……

日常直接提需求或纠正即可，不必每次说“记住”。没有新经验，不额外造记录；范围明确的改进，助手应完成修改、写回、读回核验后简短报告。需要区分“只改这一次”还是“以后也这样”时，才简短询问。

普通聊天如果不能读写本地文件，可以将相关文档作为附件提供，但不能据此认为经验已自动持久保存。

## 在 Codex 中使用

将整个 `sanjiu-evolve` 文件夹复制到你的 Codex 技能目录，保留 `SKILL.md` 与 `references/` 的相对位置；可让 Codex 先定位当前配置的技能目录。确认技能已可发现后，可以用 `$sanjiu-evolve` 调用。仅复制文件不代表所有已打开聊天已经重新加载。

需要持续项目接续时，把下面的简短入口合并到现有项目 `AGENTS.md`，将占位路径替换为本机实际路径；保留已有指令，勿整份覆盖：

> 处理本项目脚本、提示词、需求纠正或任务接续时，读取 `<实际位置>/sanjiu-evolve/SKILL.md`，并核对本项目现行规则和当前任务记录。新聊天、分支、压缩后或加载状态不明时重新核对；同一上下文已读且未变不必重复全文。经验写回依已有本地授权，不由这个入口扩大权限。

这是助手应遵循的读取入口，不能拦截分支按钮或强制宿主加载。接续时仍应核对当前项目、最新要求与素材。

## 包里有什么

| 文件 | 用途 |
| --- | --- |
| [SKILL.md](SKILL.md) | AI 的工作入口 |
| [创作方法](references/创作方法.md) | 需求边界、表达、运镜、节奏、参考映射和交付默认 |
| [经验与接续](references/经验与接续.md) | 从纠正中积累、读取相关经验、恢复当前任务 |
| [项目记录模板](references/项目记录模板.md) | 没有现成记录时可复制的空白示例 |

优先复用项目已有记录。没有时，可在使用者的项目内使用 `.local/sanjiu-evolve/`，先确认该目录被版本控制忽略且未被跟踪，再保存真实内容。这个仓库只放方法和空白模板，不把客户资料、私人聊天、原始素材或本机配置放进来；私有仓库也不等于获得了这些资料的上传授权。

本仓库采用文件白名单。以后新增要分享的方法文件时，先明确加入 `.gitignore` 的允许项；不要强行把本地工作记忆加入版本控制。

## 什么叫“进化”

发现问题 → 修好当前成果 → 判断适用范围 → 更新对应方法 → 在后续实际工作中核对效果。记录仍待验证的效果，避免把“写进文件”说成“已经有效”。例如，把“一次简单铺垫太拖”总结为按信息量分配时长，不能总结成所有镜头统一三秒。

这套方法不训练模型参数，不运行后台扫描，不会自动收集其他人的聊天，也不保证从资料中找全所有信息。当前依据是 Sanjiu 的真实创作反馈；尚未完成多人试用验证。后续先积累各人的实际反馈，再按需要合并脱敏方法，处理适用范围和冲突，不以人数多少代替判断。
