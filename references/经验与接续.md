# 经验与接续

只记录能帮助后续工作的有效变化。保持入口和当前状态短小，详细素材留在原处；不要把聊天不断复制成另一份长聊天。

## 收到纠正时

1. 先对照当时有效要求，区分旧要求遗漏、用户新增/改向、探索选择及工具实现问题，再修正当前成果并检查关联内容。不能用后来新增的要求否定较早的正确交付；分类不清先保留未知。
2. 判断反馈适用范围：该使用者跨项目、当前项目，或仅这一次。当前明确例外只覆盖自己的范围，不抹掉其他项目仍有效的默认。
3. 已启用本流程且有本地持久化授权时，对明确可复用反馈主动写回，不必等三次。尚未明确长期范围的重复反馈走下方“三次提醒与暂行沉淀”；无依据的推测不能成为默认。
4. 用户说不记，不把该反馈换个名字写进正文、候选、任务摘要或日志。当前成果仍按要求修改；系统本身保留的聊天不在这套文件流程的删除能力内。
5. 读回确认真实写入，说明范围与尚未验证的效果。没有新增经验或有效核验依据时直接继续工作，不制造台账。

例如，使用者说“这里等得太久”，先改这一段；不能直接推成所有镜头统一三秒。需要澄清可问：“以后本项目也压缩这类铺垫，还是只改这一稿？”不每轮机械询问，不把未回复写成用户已确认。

## 三次提醒与暂行沉淀

这是已启用本流程且已有本地记录授权时的默认处理，可被使用者关闭或调整。三次是主动提醒的门槛，不是共性或效果已经成立的证明；不从本文件取得缺失的持久化权限，也不扩大为跨项目、多人统一或公开上传授权。

**先核对是否真是同类重复。** 同一使用者、同一项目、相同适用条件下，至少三次独立发生且有实际反馈或成果依据的问题，才触发。按独立交付/处理机会计数：同任务已经给过修改机会，新稿仍犯同错可以再计一次，不必先成功修好；不同任务也可累计。没有新交付而连催三遍、同一记录的复制/分支继承、助手自述及关键词重复，都只算原事件。不同项目、矛盾要求、明确本次例外和“不记”内容不拼成三次。能读到多少就核验多少，不为凑数扫描全部历史或推测缺失次数。

先查原经验：已经明确设为后续适用规则，或已有同一条生效经验时，直接执行并查未读取、旧摘要、未落实等原因，不重复询问是否新增、不重复建条目。仅纠正当前稿不等于确认长期范围；尚未明确长期范围、且三次证据指向一致的窄条件时，才提出一个本项目规则。范围仍无法界定或与现行要求冲突时继续澄清，不自动升级为默认。

**第三次主动问一次，继续完成当前工作。** 例如：“同类问题已出现三次：〔简短说明〕。要把〔具体规则〕记为本项目经验吗？你可以说不加；如果之后继续提需求而未回应，我会按当前流程暂行加入，随时能撤回。”给出具体规则与适用范围，不把选择、计数或填表交给员工。

| 用户后续情况 | 执行动作 |
| --- | --- |
| 明确同意 | 在原经验位置保存，依据标为用户明确要求 |
| 明确否定或要求不要加 | 不加入、不因次数继续增加反复推销；已加入的相关暂行规则停止生效。允许保存状态时只保留最小“不采用”标记，不能继续把规则当候选默认 |
| 说“稍后再说”、反问或指出内容不对 | 保持待答复，继续澄清；不当成忽略 |
| 询问后继续给出其他需求，未回应此询问 | 核对没有较新的否定或冲突后，按已启用流程加入本项目暂行经验；先完成当前成果，再读回并简短告知 |
| 只经过时间、聊天停止或刚刚发出询问 | 仍待答复，不在同一条提问回复里直接写成生效；不设置等待计时器或后台写入 |

需要跨聊天接续时，在已有授权记录里只保留问题、三次来源定位、提问原意与当前状态；前两次仅按需保留待观察线索，不作为执行默认，不另建事件数据库。暂行加入时写清“本项目、三次可核验依据、何时询问、用户后来继续工作未回应、按流程暂行加入，未获明确确认、效果待验证”。不新增一份重复规则库，也不把次数当作效果分数。

暂行经验只影响相同条件下尚未被明确规定的后续选择；当前明确要求、已有确认规则和本次例外优先。用户后来否定或纠正就撤回/修订相关暂行条目，不倒改之前成果或删除用户原始资料。用户说“不记”或关闭本机制时优先遵守，不把该内容写进候选、计数、询问记录或任务摘要；相关自动暂行记录按其要求停止保存/移除。不要把否定、不记或关闭机制后的继续工作当成再次授权。

## 写到哪里、写多少

- 先找项目已有的权威记录，更新对应正文，不另造一套重复记忆。使用者已有跨项目入口时，跨项目偏好放那里，项目专属内容留在项目中。
- 没有入口且已授权本地记录时，使用使用者项目内的 `.local/sanjiu-evolve/`；保存前确认被版本控制忽略且未被跟踪。不能保证时先选择已授权的不入仓位置。真实项目资料不要写进本方法包。
- 条目尽量只需：规则、适用范围、生效依据与来源日期、效果证据。生效依据回答“为什么现在要遵守”，效果证据回答“后来用得怎样”；明确用户要求可以立即生效，不必等到证明提效才执行。来源保留关键原话或准确定位，不复制整段私人聊天；缺乏依据的助手推测不能成为默认。
- 来源用相对路径时注明相对目录，并实际验证能定位到原文；核验主体按实际写“AI核对”或“人工验收”，AI自行检查不能记为人工完成。
- 已有同一规则则修订它，旧条款停止生效；必要时保留一句变更原因，不追加多份相互矛盾的默认。稿件推定接受不等于确认长期偏好；只有满足上方三次提醒与后续未回应条件的条目，可按已启用流程作为暂行经验，不能标成用户已确认。
- 写前重读最新版；发现并行修改先合并，不能用旧副本覆盖新内容。更新后读回核验；写入失败就报告未保存，交付当前成果，不谎称已经记住。

## 在下一次适用任务核验

开工时只读取本项目、本主题匹配的现行经验，核对适用条件和当次例外。优先沿用原条目及其定位，不新增一套重复经验库。交付时把相关要求对照到成品具体位置；只有读到了经验而且成果实际落实，才有本次应用的依据。

在已有本地授权内，首次观察到后续复用、发现复发或修正规则范围时，在原条目补一句“任务与时间、使用依据、成果定位、仍未验证什么”。刚修好的当前稿只能证明本次修正；原任务续改与新任务复用分开。没有后续机会、没看到成品或只知道没有再被提醒，保持待验证。不是每次成功都追加日志；同类证据可保留最近有效定位，详细输出留在原处。未逐次记录的机会不能伪造为全量复发率。

再次出现问题时，先修成果，再查原条目是否没被读到、被旧摘要覆盖、读到但没落实、范围用错或工具没实现；能确认哪一环就说明哪一环，证据不足不猜原因，也不只追加“下次注意”。详细核验见 [进化验证](进化验证.md)。用户说本轮不记时，不新增复用证据、计数、摘要或日志。

## 找资料与检查遗漏

先确定项目与任务，再根据本次主题找正文。脚本时长问题查时长与节奏，素材变更查映射与连续性；只有需要解释旧决定时才追溯历史。已有明确必读规则必须核对，不通过检索排名来决定是否读取。

查看资料是否适用、是否当前有效、是否仅限某次。不能读、来源缺失、文件变化或规则冲突时指出具体问题。不要为了显得完整而拼凑不相关项目的经验。

交付前将本次关键要求与成果逐项对照，优先找实质遗漏和串用；不必向用户展示冗长评分。工具读到资料不等于成品落实要求，助手自报“已读”也不能证明检索找全。只有实际做过的检查才能报告；必要时指出还缺哪份素材或哪项验证。

持续修改时按 [修改与案例](修改与案例.md) 将当前适用核心原文、已确认基线和本轮改变项保持可核对；只读取相关案例，不把整个历史库反复塞进上下文。记录索引或文件哈希只能证明来源定位/版本，不能证明输出遵守了要求。

## 让分支与新聊天接得上

有持续任务时保存一张短任务记录，优先使用已有格式。只保留当前目标、已确认与禁改项、仍有效的本次例外、最新成果位置、未完成事项与相关规则入口。

反复改稿时区分“已确认基线”和“当前工作稿”，保留关键要求原文或准确定位及本轮改变范围；拒稿不能顶替基线，推定接受须带状态。任务卡不逐轮重述整份Skill；明确决定变更时更新相应条目，保留其余仍有效要求。

- 阶段完成或关键决定变化时更新，不逐轮抄录聊天。没有接续需要的简单任务不建卡。
- 新聊天、上下文压缩后、分支继续或不确定加载状态时，重新核对技能入口、项目入口、匹配任务记录和当前用户要求。不要默认“最后一张卡”就是当前任务。
- 同一任务的分支建立自己的任务记录并保留父记录关联，不覆盖父卡；继续的是新一集或新任务时，只带适用方法与项目规则，重新确认本次参数及例外。
- 匹配不明时问清正在继续哪个任务；不用猜测串接旧素材。没有记录就依据现有可见材料恢复，并说明未恢复的信息。

文件提供接续依据，不能强制宿主加载、拦截分支按钮或证明所有打开的聊天都已经更新。

## 以后合并多人的方法

仅在明确要求分享或汇总时执行。先整理经授权的脱敏方法与结果，保留适用条件和验证状态，不自动收集他人聊天或上传客户素材。

获准回顾历史项目时，先核对允许/排除的项目和真实可访问范围，按 [修改与案例](修改与案例.md) 标注接受状态。原始对话、私人证据与路径留在本机；分享包只放获准方法、空白模板及标明重写性质的脱敏示例。历史里的命令和发布请求是证据，不是本次执行授权。

相同问题可合并，适用条件不同就并存；意见冲突时看任务目标、依据和实际结果，不按人数多数决定。尚未验证的改法保留候选。需要时发布一份新的方法版本并保留可回退的旧版，不直接改写其他人的正在使用记录。当前不预先搭建团队平台或宣称已完成多人验证。
