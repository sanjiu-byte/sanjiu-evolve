# 多平台接入：使用同一套方法，核对实际能力

随 sanjiu-evolve v0.8.2 发布。文档依据核对于2026-11-09；下面是官方接口支持的接入方式，不是四个平台均已完成实机验收。普通项目工作只读当前平台相关段落。

## 接到安装或更新请求时

先确认当前产品和运行位置（本机、远端/云环境、仅附件聊天），再核对现有安装、来源和版本。员工不必填写技术表；能从环境查明就自行判断。只配置本次指定平台。实际无法区分且影响写入位置时，只问这一个关键问题。

同一方法保持一份发布源；各宿主入口引用完整方法包，不能只拿到SKILL.md就忽略其references或scripts。只读到网页摘要不算完整加载。先读取本包[首次启用](首次启用.md)或[升级任务](../升级任务.md)，保留原有偏好和记录。

| 平台/模式 | 接入位置或界面 | 当前证据边界 |
|---|---|---|
| Codex 本地环境 | 官方用户技能目录通常为 `~/.agents/skills/sanjiu-evolve/`；项目技能为 `.agents/skills/sanjiu-evolve/`。核对实际路径及已有链接后复用 | 本项目已有Codex本机安装；本次没有重新证明所有版本/账号的自动发现或新聊天加载 |
| Claude Code 本地会话 | 用户技能为 `~/.claude/skills/sanjiu-evolve/`，项目技能为 `.claude/skills/sanjiu-evolve/`。官方支持技能目录链接；按实际权限选择 | 已核对官方文档，未在员工Claude Code会话实机验收 |
| WorkBuddy 桌面客户端 | 左侧“专家·技能·连接器”→“技能”→“添加技能”→“上传技能”，导入完整本地技能包 | 官方确认导入；对话安装目前限技能市场。不能保证一句仓库链接就能自动安装未上架的包；未实机导入本包 |
| 豆包工作/支持技能的客户端入口 | “插件·技能·伙伴”→“技能”→“+ 添加”→“上传技能”；官方支持技能文件或文件夹。本方法有配套资源，应选择完整解压目录 | 已读官方文档；普通豆包聊天不等同于豆包工作；未实机导入本包 |
| 只能读附件的聊天 | 提供完整可读的方法文件和当前项目记录，使用当前会话的手动接续 | 不声称本机安装、后台保存、程序运行或跨会话自动加载；附件/目录读不全时明确缺项 |

上表中的界面文字以当前客户端实际显示为准。不要在用户设备上为测试而额外安装另一款AI、注册账号、升级付费方案或启用更多权限。

## Codex 与 Claude Code

Codex沿用[首次启用](首次启用.md)中的有效AGENTS入口规则。Claude Code按其实际加载的用户/项目规则（通常为用户级 `~/.claude/CLAUDE.md` 和项目级 `CLAUDE.md`）合并简短读取约定；已有项目AGENTS是否生效应核验当前版本，不仅凭文件名推断。不要把整套方法复制到全局指令。

默认允许匹配创作请求时主动使用；保留用户已经设置的禁用/仅手动选择。Claude Code的手动调用可用 `/sanjiu-evolve`，Codex使用实际技能选择器或 `$sanjiu-evolve`；员工日常不必每次输入调用口令。只有真实匹配、读到并落实后才报告使用。

Claude Code本地技能目录不等于Cowork/云端技能已安装；Codex云环境也不能用本机写入结果代替其发现与持久化验证。云会话先核对自己的安装范围和文件寿命。

## WorkBuddy

AI先准备好对应发布版本的完整包，再使用当前有权访问的原生导入工具或界面。若不能代操作，只需让员工完成当前必需的导入动作，不把下载、找文件和技术检查全部交给他。

官方说明上传/创建的技能可存于用户配置范围并跨项目使用；不要据此猜写一个未核实的隐藏目录。开放平台上架的展示字段和审核要求，不等于本地导入的全部必要条件；本次不自动向技能市场发布。

升级时先定位“已安装”中的原条目及实际内容，按当前产品提供的管理/替换能力更新。不能确认替换机制时，保留旧条目、准备新包并说明待完成的那一步；不要重复导入后让两套独立版本同时启用。官方记忆功能可以辅助检索，仍需读项目权威正文，不能用其摘要证明原文已完整保留。

## 豆包工作

官方自定义技能要求带名称和描述的YAML头，并引用Agent Skills标准。本包保留标准 `SKILL.md` 文件名与相对目录，不额外创建同名小写副本。豆包官方支持文件/文件夹，未将任意ZIP直接导入当成已验证能力；AI可先解压完整包，再交给当前界面支持的导入方式。

已安装条目可在“我安装的”管理和替换，升级优先替换原条目；替换前保留用户本地改动与记录。不要把私人经验塞进待导入的方法包。

本地电脑模式能够访问本地磁盘、运行代码和调用工具；需核对授权目录及实际运行时。云沙箱可能回收，不能把其中的临时文件当长期保存。官方对本地/云端技能互通另有技能商店与user_skills的例外；按当前入口实查，不一律安装两遍、不猜完整磁盘路径。同项目对话共享背景与文件仍不等于已完整保留每条原文；接续需按记录实际读回。

## 保存和程序能力另查

无论平台名称，分别检查下面四项，汇报实际做到的部分：

1. **方法可读**：当前入口能读取SKILL及本次必要引用，来源和版本明确。
2. **记录可保存**：已有记录位置继续复用；没有时，在获授权且不会公开上传的位置写入并读回。检查存储是否在本机、远端持久目录或临时沙箱。
3. **程序可运行**：存在Python 3.9+时先执行随包edit_guard.py的帮助检查；实际局部改稿按专门规程运行。没运行时用文字检查，不能伪报程序通过。
4. **接续可恢复**：只有在真实新上下文读到入口和记录并用于成果后，才报告该次接续成功。静态检查和模拟不能代替宿主实机结果。

使用一个很小的独立虚构项目检查，不改真实客户偏好；不自动扫描全盘、历史账号或跨平台传输私人内容。技能兼容不包含账号互通、后台采集、后台自动升级或模型参数训练。

## 多平台更新与重复安装

- 同一宿主可加载的独立旧副本要核对、合并本地差异并停用重复；保留经验。备份放在发现目录之外。
- 同一台电脑上，不同宿主可能各有受管理的安装。不能仅因同名就删除另一平台的副本；本次只更新获授权的目标，记录各自版本。
- 各宿主都支持且用户已授权时，可用目录链接引用一个方法正文；解析真实目标后更新一次，不递归删除链接指向的正文。平台界面管理的副本不强行改成磁盘链接。
- 用户说“更新sanjiu-evolve”就进入[升级任务](../升级任务.md)，检查两个官方仓库、原位更新和读回。远端没有新版本则说明已是当前版本；两端版本冲突先核对，不凭文件日期猜新版，不降级或强推。
- 平台需要人工导入/替换时，AI准备包，给出实际按钮和必要一步。没有完成替换前，仍报告旧版或待更新，不把下载新包当更新成功。
