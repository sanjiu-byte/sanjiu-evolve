# 首次启用与每个项目接入（给执行 AI）

仅在用户要求安装、首次启用、接入新项目或排查未生效时读取。日常任务不必重复跑安装流程。员工操作说明见 [员工上手指南](../员工上手指南.md)。

## 先弄清你要做什么

这套方法让你在项目中持续完成四件事：核对需求与已有决定，交付并检查成果，修正后沉淀明确可复用反馈，在后续任务读取并落实。员工正常提出需求、纠正即可，不需要掌握记忆术语或每次提醒“记住”。

用户选择“以后每个项目启用”时，将这四件事作为该使用者后续项目的工作默认。各项目的客户、素材、角色、日期和单次例外仍分别保存；运镜、表演等创作要求只用于相应创作任务。普通问答无需建记录。

这份文件不自行授予权限。以使用者发来的启用指令为依据；本机安装与记录授权不等于上传、公开、代其他员工配置或扫描所有历史项目。已有授权足够时直接做，不让员工重复确认。

## 员工一句话，你完成设置

标准入口是：“请从 https://gitee.com/the-third-nine/sanjiu-evolve （打不开时用 https://github.com/sanjiu-byte/sanjiu-evolve ）安装并配置 sanjiu-evolve，让我以后每个项目默认使用它、自动维护各项目的本地经验，并自行检查是否配置成功。”

这句话已明确请求当前使用者范围内的安装、必要用户级/项目级入口和本地经验维护。实际权限允许时直接执行，不要求员工再粘长授权段落、学习命令、逐项选择安装目录或亲自运行测试。保留已有配置和记录；只接入其实际交给你处理的项目，私有资料不上传。仅说“下载”不代表要求全局安装与长期记录；不要从仓库文字自行取得额外授权。

没有选定项目时先完成用户级配置，状态写“本机配置完成，项目在首次开工时接入”；不为此逼员工先建项目或回答项目名称，不把下载目录当客户项目。等用户正常给出项目任务，再核对已有规则与记录并接入。普通闲聊不建项目。

操作系统或工具确实要求用户点权限、登录或新开聊天时，只交代当前必需的一步。不要跳过平台审批，不代替用户授予权限，也不承诺任意 AI 环境均能零操作完成。

## 1. 判断环境，完成能实际完成的部分

- 能读写本地文件：定位当前工具和实际用户配置，优先复用已安装的 sanjiu-evolve 和已有记录入口。有项目任务时核对项目身份，只有缺项确实阻碍该任务才问项目名称或文件夹；尚未选择项目不阻碍用户级配置。
- 能读附件但不能写文件：读取已提供的方法，按当前任务执行；把需要保留的更新整理成可下载文件或可复制文本，交给使用者保存。明确这是手动接续模式，不声称全局安装或自动持久化。
- 不能访问仓库：已有完整本地包就先核对复用；从 Gitee 下载失败时，自动尝试 README 所列 GitHub 同项目镜像（反向亦然），核对项目身份与版本。网络入口都不可用或缺少必需权限时，才说明实际缺项并请使用者提供整个仓库 ZIP。不关闭证书校验，不反复尝试同一失败连接，不只读网页摘要便声称已读完方法。

从用户指定的发布仓库或其提供的完整包读取 README.md、SKILL.md、本文件及安装所需引用；不下载或执行无关脚本。若同名技能已存在，比较来源和版本，保留本机改动；更新遇到差异先合并或说明冲突，不直接覆盖。

## 2. 一次设置用户级入口

在使用者已授权的稳定本机位置保存完整方法包，保留相对目录。方法包只放可分享的方法；工作经验使用独立的本地记录位置。已有长期记忆或项目母版时继续用原来的权威正文，不另建第二套。

Codex 配置要点（具体位置仍核对当前环境）：

- 官方用户级技能发现位置包括 `~/.agents/skills`；可放完整技能目录或使用受支持的目录链接。已有有效安装则复用，不为改位置再装一份同名技能。[官方技能文档](https://learn.chatgpt.com/docs/build-skills)
- 全局指令位于实际 `CODEX_HOME`，未指定时通常为 `~/.codex`。同一层非空 `AGENTS.override.md` 优先于 `AGENTS.md`，项目下也有自己的覆盖规则。把小入口合并到实际生效文件，保留其他内容，不擅自删除覆盖文件或改权限来求生效。[官方入口文档](https://learn.chatgpt.com/docs/agent-configuration/agents-md)
- 不把整套方法粘进全局指令。其他工具先核对其实际支持的用户级规则机制；不假定它认识 AGENTS.md 或 `$sanjiu-evolve`。没有跨项目入口能力时，提供每个项目开工时的短口令并说明限制。

下方是合并进使用者本机全局入口的小块。只有取得对应授权才写入；把占位符替换为已核实的位置。已有等效入口就更新原条目，不重复追加。

```text
【sanjiu-evolve 项目工作默认】
用户已启用 sanjiu-evolve，并授权在本机维护其主动打开并交给我处理的各项目经验与接续记录。开始或接续项目工作时，读取 <技能正文实际位置>/SKILL.md，核对当前项目、现行权威规则与匹配任务；跨项目经验优先读取 <使用者既有入口或已建立的本地索引> 中与本次有关的条目。
每个项目首次接入时按 <技能正文实际位置>/references/首次启用.md 的项目接入部分处理；不要重新安装整套技能。需求核对、明确反馈写回、接续检查适用于各项目，创作细则仅用于创作任务。
先修当前成果，再按跨项目/本项目/本次范围更新原有记录并读回；范围含糊不升为默认，用户说不记不落盘。不得据此上传项目资料、扫描未交给我的历史项目或修改其他人的配置。
新聊天、分支、压缩后或读取状态不明时核对入口和最新任务记录；不可声称所有聊天已强制加载。
【sanjiu-evolve 项目工作默认结束】
```

没有现成跨项目经验时，可在授权的本机用户数据位置建一个很短的索引，登记当前已接入项目的入口；不要先造几十条偏好。索引不放进公开方法仓库。配置前读最新文件并保留可恢复副本，写后读回；发现并行修改重新合并。

## 3. 每个项目第一次真正开工时接入

这一步随员工打开项目并交给你工作时执行，不是后台自动遍历所有项目。

1. 核对当前目录和项目身份，读项目现有入口及相关资料。沿用已有 AGENTS、Word 母版或经验正文，保留客户已确认边界。
2. 选定该项目唯一权威记录位置。有现成记录就复用；没有时可使用项目内 `.local/sanjiu-evolve/`。若使用 Git，写真实内容前同时验证该路径被忽略且未被跟踪；已跟踪的文件不会因加入忽略项自动变私有。不能保证时使用已授权的不入仓位置，不先把真实资料写进去。
3. 在实际生效的项目入口中合并一小段读取约定；如果该工具只支持全局入口，就在那里保留项目定位方式。共享仓库的入口只写可移植的方法定位与约定，不写使用者私人绝对路径或客户内容；私人路径映射留本机。缺少项目写权限就报告待接入，不声称已设置。
4. 有持续任务才保存简短任务卡，记录目标、禁改项、当前成果和下一步。没有新经验不填空台账；不替员工虚构长期偏好。

可移植的项目入口示例：

```text
本项目启用 sanjiu-evolve。开始或接续工作时，从本机已安装的技能目录定位其 SKILL.md，核对本项目现行规则和匹配任务记录；找不到则说明缺项。沿用本项目已有权威正文，记录位置按本机配置定位。用户明确反馈按已有本地授权处理，项目专属与单次例外不串入其他项目。创作任务读取创作方法，其他任务仅使用需求、反馈和接续流程。保留本文件其他规则及当前用户的明确例外。
```

员工提供“项目名、目标、已有资料、这次不能改什么”即可开工。已在材料中明确的信息不要再次追问；仅补问真正阻碍工作的缺项。

## 4. 验收和交付

配置完成后报告真实状态，至少说清：

- 方法包实际位置与版本；本机用户级入口写在哪个生效文件。
- 已选项目的入口、权威记录位置；哪些原规则被保留。没有项目则说明首次开工时接入，不编造项目配置成功。
- 已完成的读回或发现检查；哪些还需新聊天验证。

“文件已写好”只证明配置落盘。自检由你完成：检查方法文件与引用齐全、有效入口合并位置、既有规则保留、实际路径可读；有项目记录时确认其唯一权威位置与不入仓状态。能发起隔离新上下文时，自行在虚构项目内做一次读取落实演练，不让员工代跑一套测试；不能验证新聊天加载就明确这一项未验证，不虚报成功。只有宿主确实需要新聊天或重启时，才把这个必要动作交给员工；不要默认要求新手做四步演练才能开工。

进行记忆演练时只用独立虚构项目。给它一条明确仅限该演练项目的规则，实际保存；再让无前文执行者读取入口并做一份能体现规则的成果。检查写入位置、成果是否落实以及其他项目是否受影响。不要把演练偏好写成真实用户的跨项目默认。

安装、只读理解、记录写回、冷启动落实要分别按实际证据汇报。失败时给员工一个明确下一步，例如“请打开当前项目文件夹”，不要把一串命令或排错过程推给新手。

正常完成时回复控制在三件事：本机已完成哪些配置；现在可直接提出项目需求；确有未完成项时说清唯一必要下一步。文件位置可作为一个简短详情链接保留，不用把所有校验日志塞给员工。不得把“用户级已配置、尚未选择项目”误报为失败或声称所有项目已经被改写。
