# sanjiu-evolve · 三九·创作进化

版本：0.9.0。员工复制下面一句话即可开始；遇到问题看 **[员工上手指南](员工上手指南.md)**，验证范围见 [检查报告](CHECKS.md)，本次变化见 [旧新版对照](版本对照.md)。

帮助你更快进入想要的创作方向，并且越用越懂你的判断。基于详细需求和每次调整持续进化：先改善当前成果，再保存适用经验，并在后续任务核验是否用上。

第一版采用 Sanjiu 已在实际工作中使用、持续修正的创作方法。先把这一套用好，暂不拆成“个人版”和“通用版”。这些是可调整的工作默认，不是所有创作者都必须遵守的标准；具体客户要求和本次明确决定优先。

## 员工从这里开始

打开你正在使用的 AI，发送这一句话；AI 先识别当前平台，再完成可执行的安装、配置和检查：

```text
请从 https://gitee.com/the-third-nine/sanjiu-evolve （打不开时用 https://github.com/sanjiu-byte/sanjiu-evolve ）安装并配置 sanjiu-evolve，让我以后每个项目默认使用它、自动维护本地经验，保存相关对话原文、各版稿件、反馈理由和附件，并自行检查是否配置和保存成功。
```

具备本地安装和入口能力时，等 AI 报告配置结果，就可以正常说项目需求，例如：“这是新品介绍项目，根据这些客户要求写一版15秒脚本。”不用每个项目重复安装或再说一遍启用口令。暂时没有项目也能先完成用户级配置；以后首次真正处理项目时由 AI 接入。平台只允许界面导入时，由 AI 准备完整包并给出必要的一步；只能读附件时采用手动接续，不报告本机安装成功。

**多平台接入：**新增 Codex、Claude Code、WorkBuddy 和豆包的接入分流，仍使用同一套方法。各产品的原生技能、文件保存和程序执行能力分别核验；当前适配依据与未实测范围见 [多平台接入](references/多平台接入.md)。普通聊天与支持技能的工作模式不混称；跨平台使用不自动同步私人经验，也不启用自动更新。

需要界面导入时使用 [v0.9.0完整ZIP](https://github.com/sanjiu-byte/sanjiu-evolve/archive/refs/tags/v0.9.0.zip)，不要只上传单个SKILL.md。平台要求文件夹时先由AI解压，保留全部相对资源；受支持的具体导入格式以当前客户端核验结果为准。

**已经装过：**直接说“更新 sanjiu-evolve”，或把 [升级任务.md](升级任务.md) 作为文件交给 AI。它应找到当前平台的原安装、就地更新并核对重复入口，保留你已积累的经验；不用自己卸载或找路径。首次安装指令发现旧安装时也走同一升级流程。需要界面替换的平台，由 AI 准备完整包并告诉你必要的一步。

**给收到这句话的 AI：**先读本仓库的 [SKILL.md](SKILL.md) 和 [首次启用](references/首次启用.md)，按使用者明确要求实际下载、配置、读回并自检，不把安装教程再交还员工。既有配置与私人记录保留，项目资料不上传。只说“下载”且未表达安装启用意图时，不自行扩展为修改全局默认。

这适用于具备相应能力和权限的 AI 工具。需要你点权限时，AI 应主动说清“为什么、写哪个文件夹、点哪个实际按钮”，批准后继续，你不用重发任务；不统一要求切换Full access。读取方法受阻时也应明确告知，不能只说已经接入。确实要求新聊天才能加载时，AI 应只告诉员工这一个下一步。只能聊天、不能写文件的环境使用附件模式，不能做到自动本机配置。备用仓库：[GitHub](https://github.com/sanjiu-byte/sanjiu-evolve)。

**权限或连接问题、日常纠正、换聊天与换电脑，见 [员工上手指南](员工上手指南.md)。这些是备用说明，不是员工必须先完成的一套操作。**

## 更新与排障

更新时只需说：

```text
更新 sanjiu-evolve
```

还没读过本方法的AI，可补完整一句：“请从 https://gitee.com/the-third-nine/sanjiu-evolve （打不开时用 https://github.com/sanjiu-byte/sanjiu-evolve ）读取升级任务，在当前平台的原安装上更新sanjiu-evolve，保留我的经验和配置，检查不要同时启用独立旧版。”

遇到问题可直接说“检查sanjiu-evolve为什么没生效”。AI先只读检查当前平台、版本、入口与实际错误；涉及写入按已有授权处理。更新不会自动同步其他电脑、账号或私人经验，也没有后台自动更新服务。

## AI 收到这套方法后做什么

资料保存是接入的一部分：完整原文、各版稿件、正负反馈及理由、必要附件保存在使用者自己的已授权位置，经验卡只放简短结论和原件入口。首次缺目录或授权范围时简单问一次，后续主动保存并读回；更新方法时保留原资料。具体见 [资料保存](references/资料保存.md)。

| 时机 | 应完成的事 |
| --- | --- |
| 第一次启用 | 按 [首次启用](references/首次启用.md) 核对工具能力、配置本机入口，并说明真实完成度 |
| 每个项目开工 | 找当前项目已有规则与记录，分清必须做到、禁止或未经允许不改、AI可自行优化的范围；只带入适用要求 |
| 持续修改 | 核对当前要求与基线；局部改稿由 AI 调用工具保留范围外原文，再检查范围内的情绪和意思 |
| 员工指出问题 | 先修成果；按已有授权沉淀明确可复用的纠正，不要求每次提醒“记住” |
| 同项目同类问题独立出现至少三次 | 主动询问；否定不加，之后继续工作未回应则按已启用流程加入可撤回的本项目暂行经验；不记优先 |
| 后续遇到相似任务 | 读取适用经验，对照实际成果；首次复用或复发时补充依据，不把“已保存”当“已有效” |
| 新聊天或分支继续 | 重新核对入口、最新任务及例外，用成果体现已经落实 |

这套工作流程适用于后续各项目；运镜、表演和时长等创作细则只用于创作任务。普通闲聊不建立项目台账。只读附件的聊天可使用手动保存模式，不能据此声称完成跨项目自动接入。

Codex 的本机技能发现和全局入口需要按实际配置核对，具体做法交给 AI 阅读 [首次启用](references/首次启用.md)。安装与配置不代表全部已打开聊天立即重新加载；新聊天自检步骤在员工指南中。

## 什么叫“进化”

v0.6.0 增加三次提醒与暂行沉淀，帮助不习惯主动记经验的人。它只在已启用流程且已有本地记录授权内工作；三次必须有可核验的独立事件，询问当轮不立即默认加入。用户之后继续提需求却未回应时才暂行保存，明确标记未获确认；否定、不记或关闭机制优先。已有规则反复没落实时查执行原因，不重复堆同一条。具体见 [经验与接续](references/经验与接续.md)。

发现问题 → 修好当前成果 → 判断适用范围 → 更新对应方法 → 在后续实际工作中核对效果。记录仍待验证的效果，避免把“写进文件”说成“已经有效”。例如，把“一次简单铺垫太拖”总结为按信息量分配时长，不能总结成所有镜头统一三秒。

v0.5.0 补上经验的后续核验与共享回收：明确要求可立即按范围生效，效果依据另行积累；新增需求不倒算成旧稿错误；没有后续应用机会就保持待验证。收回来的案例先核对原文、时间线和重复，再决定是否进入下一版。员工正常提需求，不能让员工填写技术配置；回收包由本人核对后手动交回，不自动采集或上传。

保留v0.4.0的局部改稿程序：按选定片段拼回全文，范围外保持原文，输入变化时拒绝继续用旧会话。AI负责选对修改范围、读取最新权威要求，以及检查情绪与意思。程序通过不等于作品合格；宿主是否每轮调用仍取决于实际执行，不能承诺彻底消除遗忘。缺少运行条件时退回文字检查，明确未运行程序。

简短默认压缩冗余表达，不削掉关键情绪或既定画面。历史学习区分明确认可、推定接受、明确否定和状态不明；推定接受只标稿件状态，不能当作发布授权或长期规则确认。具体边界与正反示范见 [修改与案例](references/修改与案例.md)。真实案例测试及效果限制见 [检查报告](CHECKS.md)，不以模拟通过宣称员工返工率已下降。

这套方法不训练模型参数，不运行后台扫描，不会自动收集其他人的聊天，也不保证从资料中找全所有信息。当前依据是 Sanjiu 的真实创作反馈；尚未完成多人试用验证。后续先积累各人的实际反馈，再按需要合并脱敏方法，处理适用范围和冲突，不以人数多少代替判断。
