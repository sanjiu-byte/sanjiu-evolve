# 首次启用与每个项目接入（给执行 AI）

在用户要求安装、首次启用、已授权的新项目首次开工，或遇到接入/权限故障时读取相应部分。日常任务不必重复跑安装流程。员工操作说明见 [员工上手指南](../员工上手指南.md)。

## 先弄清你要做什么

这套方法让你在项目中核对需求、交付并检查成果、保存授权的完整资料、从反馈积累经验，并在后续任务读取落实。员工正常提出需求、纠正即可，不需要掌握记忆术语或每次提醒“记住”。

用户选择“以后每个项目启用”时，按其授权将这些动作作为后续项目的工作默认。各项目的客户、素材、角色、日期和单次例外仍分别保存；运镜、表演等创作要求只用于相应创作任务。普通问答无需建记录。

这份文件不自行授予权限。以使用者发来的启用指令为依据；本机安装与记录授权不等于上传、公开、代其他员工配置或扫描所有历史项目。已有授权足够时直接做，不让员工重复确认。

## 员工一句话，你完成设置

标准入口是：“请从 https://gitee.com/the-third-nine/sanjiu-evolve （打不开时用 https://github.com/sanjiu-byte/sanjiu-evolve ）安装并配置 sanjiu-evolve，让我以后每个项目默认使用它、自动维护本地经验，保存相关对话原文、各版稿件、反馈理由和附件，并自行检查是否配置和保存成功。”

这句话已明确请求当前使用者范围内的安装、必要入口、本地经验维护及相关完整资料保存。按 [资料保存](资料保存.md) 复用已有授权位置；缺位置或旧指令仅授权经验维护时，只做一次目录与范围的基础确认。实际权限允许时直接执行，不要求员工粘长授权段落、学习命令或亲自运行测试。保留已有配置和记录；只接入其实际交给你处理的项目，私有资料不因启用而上传。仅说“下载”不代表要求全局安装与长期记录。

没有选定项目时，当前宿主支持持久安装与入口且实际配置完成，才报告用户级配置成功；本地模式可写“本机配置完成，项目在首次开工时接入”。界面导入待完成或只有附件模式时报告对应状态，不冒称本机成功。不为此逼员工先建项目或回答项目名称，不把下载目录当客户项目。等用户正常给出项目任务，再核对已有规则与记录并接入。普通闲聊不建项目。

操作系统或工具确实要求用户点权限、登录或新开聊天时，只交代当前必需的一步。不要跳过平台审批，不代替用户授予权限，也不承诺任意 AI 环境均能零操作完成。

## 受阻时给使用者一个明确动作

先核对实际失败返回和当前执行权限，区分方法未发现、读取失败、写入未获准与环境初始化故障。不能把“尝试读过”说成“已读并生效”。缺少方法正文时说明哪些要求尚未核对；参考素材未读到时，不以自编情节冒充参考提取。能继续的部分先做，必需素材不可读则明确保留缺项。

确需用户授权时，在系统请求旁用一句话说明**用途、目标文件夹、实际按钮、批准后继续什么**。例如当前弹窗确有该按钮时：“为了保存这个项目的要求，需要允许写入〔项目记录文件夹〕。请点弹窗里的 **Allow once（允许一次）**；批准后我会保存并检查，你不用再重发任务。”按钮和会话授权选项以当前界面为准，不能编造。用户拒绝或权限未返回时不写；能读方法就继续完成当前创作，并说明记录尚未保存。

申请前确认目标是否存在、工具是否支持给尚不存在的路径授权；新建路径确需父目录授权时，选择能完成创建的最近实际存在父目录，并说明只操作其中本项目目标。不要申请整盘，不因一次拒绝反复扩大权限。批准后实际写入并读回；已有有效批准时不重复询问。

只有实际执行模式确实不允许所需动作、且当前平台支持切换时，才指引使用者到输入框下方的权限控件选择能完成任务的模式，并说明影响。具体目录授权可完成时优先用它，不统一要求所有人切 Full access；已显示 Full access 却仍失败时，查当前工具范围和错误，不重复要求同一开关。界面模式与实际运行权限不一致时如实保留未知。[官方权限说明](https://learn.chatgpt.com/docs/permission-modes)

沙箱初始化或运行时错误不等于素材不存在，也不自动说明缺少某个业务目录授权。按当前工具支持方式检查或恢复；不擅自关闭沙箱、改ACL或停止其他聊天。无法恢复时说明未完成环节与有依据的下一步，不让员工学习整套排错命令。

## 1. 判断环境，完成能实际完成的部分

先按 [多平台接入](多平台接入.md) 核对实际产品与模式。原生技能导入、本机文件持久化、程序执行、新聊天读取分别确认；不能由品牌或“支持Skills”推断全部具备。只接入用户当前指定的平台，不顺手修改本机所有AI客户端。平台只允许界面导入时，准备包并告诉使用者必需的那一步；不能用聊天中的“已安装”替代导入成功。

- 能读写本地文件：定位当前工具和实际用户配置，优先复用已安装的 sanjiu-evolve 和已有记录入口。有项目任务时核对项目身份，只有缺项确实阻碍该任务才问项目名称或文件夹；尚未选择项目不阻碍用户级配置。
- 能读附件但不能写文件：读取已提供的方法，按当前任务执行；把需要保留的更新整理成可下载文件或可复制文本，交给使用者保存。明确这是手动接续模式，不声称全局安装或自动持久化。
- 不能访问仓库：已有完整本地包就先核对复用；从 Gitee 下载失败时，自动尝试 README 所列 GitHub 同项目镜像（反向亦然），核对项目身份与版本。网络入口都不可用或缺少必需权限时，才说明实际缺项并请使用者提供整个仓库 ZIP。不关闭证书校验，不反复尝试同一失败连接，不只读网页摘要便声称已读完方法。

从用户指定的发布仓库或其提供的完整包读取 README.md、SKILL.md、本文件及安装所需引用；不下载或执行无关脚本。发现已安装本方法时按 [升级任务](../升级任务.md) 更新原有唯一正文、处理独立旧副本和重复入口；共享方法可更新替换，本地改动先合并，私人经验与配置保留。不能把“保留原记录”理解为另装一套新版并让旧版继续生效。来源或主入口无法核实时说明缺项，不猜测覆盖。

## 2. 一次设置用户级入口

在使用者已授权的稳定本机位置保存完整方法包，保留相对目录。方法包只放可分享的方法；工作经验使用独立的本地记录位置。已有长期记忆或项目母版时继续用原来的权威正文，不另建第二套。

自 v0.4.0 起，完整包包括 `scripts/edit_guard.py` 和 `references/局部改稿检查.md`。不要只安装 SKILL.md。检查本机现有 Python 3.9+ 能否运行 `python <技能目录>/scripts/edit_guard.py --help`；选用实际可用解释器并将位置留在本机配置，不写入共享包。能运行才报告局部改稿程序可用；缺少运行能力时沿用文字检查并明确限制，不要求员工手填 JSON，也不为此擅自安装大型环境。日常局部改稿由 AI 按专门规程执行，不把安装时的 `--help` 检查冒充实际改稿验证。

Codex 配置要点（具体位置仍核对当前环境）：

- 官方用户级技能发现位置包括 `~/.agents/skills`；可放完整技能目录或使用受支持的目录链接。已有有效安装则复用，不为改位置再装一份同名技能。[官方技能文档](https://learn.chatgpt.com/docs/build-skills)
- 核对技能在当前环境可被发现且未被使用者禁用；有 `agents/openai.yaml` 时检查 `allow_implicit_invocation`。未配置时默认允许隐式调用，不因缺这个可选文件重装；使用者明确设置仅手动调用时保留，不擅自覆盖。安装可见与实际成功读取、应用分别核验。
- 全局指令位于实际 `CODEX_HOME`，未指定时通常为 `~/.codex`。同一层非空 `AGENTS.override.md` 优先于 `AGENTS.md`，项目下也有自己的覆盖规则。把小入口合并到实际生效文件，保留其他内容，不擅自删除覆盖文件或改权限来求生效。[官方入口文档](https://learn.chatgpt.com/docs/agent-configuration/agents-md)
- 不把整套方法粘进全局指令。其他工具先核对其实际支持的用户级规则机制；不假定它认识 AGENTS.md 或 `$sanjiu-evolve`。没有跨项目入口能力时，提供每个项目开工时的短口令并说明限制。

下方是合并进使用者本机全局入口的小块。只有取得对应授权才写入；把占位符替换为已核实的位置。已有等效入口就更新原条目，不重复追加。

```text
【sanjiu-evolve 项目工作默认】
用户已启用 sanjiu-evolve，并授权在本机维护其主动打开并交给我处理的各项目经验与接续记录。开始或接续项目工作时，读取 <技能正文实际位置>/SKILL.md，核对当前项目、现行权威规则与匹配任务；跨项目经验优先读取 <使用者既有入口或已建立的本地索引> 中与本次有关的条目。
用户正常提出剧情脚本、分镜、视频提示词的编写、修改、评审或参考提取任务，就主动读取并应用相关创作方法，无需其点名技能。读取失败先说明尚未落实的环节；权限确需用户点击时说明用途、目标与实际按钮，获准后继续，不把失败说成已接入。
每个项目首次接入时按 <技能正文实际位置>/references/首次启用.md 的项目接入部分处理；不要重新安装整套技能。需求核对、明确反馈写回、接续检查适用于各项目，创作细则仅用于创作任务。
每次实质改稿核对短核心要求、本轮改变项及仍须保留项，交付前与成品具体位置对照；完整参考按需读取。历史案例保留接受状态和项目范围，不把推定接受当长期规则或发布授权。
先修当前成果，再按跨项目/本项目/本次范围更新原有记录并读回；范围含糊不升为已确认默认，同项目三次重复问题按技能的询问与暂行沉淀流程处理，用户否定、不记或关闭机制时优先遵守。不得据此上传项目资料、扫描未交给我的历史项目或修改其他人的配置。
完整资料保存按 <技能正文实际位置>/references/资料保存.md 核对本人授权与目录；原文、各版稿、反馈理由及附件另存并读回，任务卡只保留原件入口。缺少目录或范围时一次确认；不能把尚未实际保存报告为完成。
新聊天、分支、压缩后或读取状态不明时核对入口和最新任务记录；不可声称所有聊天已强制加载。
【sanjiu-evolve 项目工作默认结束】
```

没有现成跨项目经验时，可在授权的本机用户数据位置建一个很短的索引，登记当前已接入项目的入口；不要先造几十条偏好。索引不放进公开方法仓库。配置前读最新文件并保留可恢复副本，写后读回；发现并行修改重新合并。

## 3. 每个项目第一次真正开工时接入

这一步随员工打开项目并交给你工作时执行，不是后台自动遍历所有项目。

1. 核对当前目录和项目身份，读项目现有入口及相关资料。沿用已有 AGENTS、Word 母版或经验正文，保留客户已确认边界。
2. 选定该项目唯一权威记录位置。有现成记录就复用；没有时可使用项目内 `.local/sanjiu-evolve/`。若使用 Git，写真实内容前同时验证该路径被忽略且未被跟踪；已跟踪的文件不会因加入忽略项自动变私有。不能保证时使用已授权的不入仓位置，不先把真实资料写进去。
   同时按 [资料保存](资料保存.md) 核对完整资料的位置和授权。得到确认后实际保存本次可访问的相关原文及文件并读回，简短记录覆盖范围；缺权限或尚待确认时标为待保存，不只建一个空目录就报告已接入保存流程。
3. 在实际生效的项目入口中合并一小段读取约定；如果该工具只支持全局入口，就在那里保留项目定位方式。共享仓库的入口只写可移植的方法定位与约定，不写使用者私人绝对路径或客户内容；私人路径映射留本机。缺少项目写权限就报告待接入，不声称已设置。
4. 有持续任务才保存简短任务卡，记录目标、禁改项、当前成果和下一步。没有新经验不填空台账；不替员工虚构长期偏好。

先写目标文件并读回成功，再登记项目索引；失败时只报告待接入，避免留下指向尚未创建文件的正式入口。原索引存在并行改动时重新读取后合并。

可移植的项目入口示例：

```text
本项目启用 sanjiu-evolve。开始或接续工作时，从本机已安装的技能目录定位其 SKILL.md，核对本项目现行规则和匹配任务记录；找不到则说明缺项。沿用本项目已有权威正文，记录位置按本机配置定位。用户明确反馈按已有本地授权处理，项目专属与单次例外不串入其他项目。创作任务读取创作方法，其他任务仅使用需求、反馈和接续流程。保留本文件其他规则及当前用户的明确例外。
```

员工提供“项目名、目标、已有资料、这次不能改什么”即可开工。已在材料中明确的信息不要再次追问；仅补问真正阻碍工作的缺项。

## 4. 验收和交付

配置完成后报告真实状态，至少说清：

- 方法包实际位置与版本；本机用户级入口写在哪个生效文件。
- 已选项目的入口、权威记录位置；哪些原规则被保留。没有项目则说明首次开工时接入，不编造项目配置成功。
- 完整资料实际保存位置、已保存到哪里及缺项；无当前资料时标“目录已确认，待首次资料”，不冒称已完成资料归档。保存受阻与方法安装成功分别报告。
- 已完成的读回或发现检查；哪些还需新聊天验证。

“文件已写好”只证明配置落盘。自检由你完成：检查方法文件与引用齐全、有效入口合并位置、既有规则保留、实际路径可读；有项目记录时确认其唯一权威位置与不入仓状态。能发起隔离新上下文时，自行在虚构项目内做一次读取落实演练，不让员工代跑一套测试；不能验证新聊天加载就明确这一项未验证，不虚报成功。只有宿主确实需要新聊天或重启时，才把这个必要动作交给员工；不要默认要求新手做四步演练才能开工。

进行记忆演练时只用独立虚构项目。给它一条明确仅限该演练项目的规则，实际保存；再让无前文执行者读取入口并做一份能体现规则的成果。检查写入位置、成果是否落实以及其他项目是否受影响。不要把演练偏好写成真实用户的跨项目默认。

安装、只读理解、记录写回、冷启动落实要分别按实际证据汇报。失败时给员工一个明确下一步，例如“请打开当前项目文件夹”，不要把一串命令或排错过程推给新手。

正常完成时回复控制在三件事：本机已完成哪些配置；现在可直接提出项目需求；确有未完成项时说清唯一必要下一步。文件位置可作为一个简短详情链接保留，不用把所有校验日志塞给员工。不得把“用户级已配置、尚未选择项目”误报为失败或声称所有项目已经被改写。
