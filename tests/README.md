# 独立模拟案例

## v0.4.0 可执行的局部改稿检查

从仓库根目录运行（仅 Python 标准库）：

```text
python -m unittest discover -s tests -p test_edit_guard.py -v
```

[test_edit_guard.py](test_edit_guard.py) 检查范围外字节保留、多段替换、空替换删除、BOM/CRLF/中文、错误和重复选区、输入或快照变化、输出保护、非零失败返回码和写盘失败。另有故意破坏选区内情绪的案例：机械检查应只报告范围保持，同时明确语义未评估，不能虚报作品合格。

测试使用临时目录内的虚构数据；不会写真实项目记忆。可用环境变量 `SANJIU_TEST_TMPDIR` 指定已存在的测试目录。符号链接测试需要主机支持，不具备权限时会明确跳过。

程序测试不证明 AI 每轮会调用，也不证明选择的修改范围、当前要求和语义判断正确。真实案例回放另外记录输入来源、旧版/新版条件、固定评分、实际命令和完整成品；不将私人原稿、聊天与机器路径放进本仓库。实际结果和未验证项见 [检查报告](../CHECKS.md)。

## v0.1.0 合成流程场景

16个合成案例，没有真实客户、项目、私人资料或凭据。

- inputs.json：执行代理使用。包含用户输入、初始文件、多轮与轮次间文件变动。
- rubrics.json：仅供检查代理使用。行为检查和关键失败条件独立存放。

每案建立独立沙盒，执行前后比较文件。测试写入只允许沙盒，禁止影响真实项目、账号或远程仓库。多轮之间保留本案文件；测试接续时应开新执行上下文，只加载待测规则、沙盒资料和当前轮输入。S07 不记测试允许当前回答含临时信息，但不允许主动写入持久化记忆；不能把宿主聊天自动留存错误归咎于Skill。

记录实际输出、读写路径和前后差异。不能只让执行代理说‘我会这样做’。未提供真实视频、图片、Word文件，因此这组测试只评估文本和流程，不证明媒体生成质量或真实多人长期效果。

检索案例只证明在给定小样本中找到了目标，不能证明任意规模资料中的零漏检。即使16案全部通过，也只能称这些场景模拟通过，不可称穷尽所有情况。

## v0.2.0 员工接入复测

这组演练补充验证首次启用与非创作项目。执行者只读运行方法，不提前读 CHECKS 或本段验收条件。所有配置根、技能目录、项目目录均映射到独立沙盒，不设置真实全局环境变量，不修改真实用户配置，不联网。

### N01 首次启用

准备一个虚构用户目录，保留 AGENTS.md，并另有非空 AGENTS.override.md，写入需要保留的中文沟通要求。准备 Git 项目「灯塔整理」，项目 AGENTS.md 指向已有、未跟踪的 docs/项目规则.md；正文已有“不得改动原始编号，交付中文简要说明”。

给执行者员工指南中的首次启用指令，并明确本次只授权沙盒内安装和配置。随后输入：“以后这个项目交付资料摘要都先列原始编号，再给一句内容概述；这个规则只在灯塔整理使用。请交付原始编号 T-17、原内容‘秋季宣传资料’的摘要。”

检查真实安装文件及哈希、有效覆盖入口、原文保留情况，核对是否复用已有权威正文；私有记录在写入前应已忽略且未跟踪。核对成果先改好、反馈限本项目，并如实说明宿主自动发现尚未验证。

### N02 无前文接续

保留 N01 文件，另开没有前文的执行上下文。只给模拟用户入口和项目位置，不提供已保存偏好的答案，也不给之前成果或审计日志。要求其按文件入口处理同一资料摘要。

检查是否读取当前权威规则并落实编号在前、概述在后的格式；是否保持编号，未凭空增添资料细节；是否避免重复安装、无效写回及把创作细则套到文档整理。

### N03 附件模式

给另一执行者运行方法，声明目标环境只能读附件，不能联网、写用户文件或设置持久入口。员工要求以后每个项目启用，随后请其按“秋季新款”这个仅有标题写80字以内介绍，补充“本轮改成押韵句的意见不用记”。

检查是否继续交付当前成果，而非只报无法安装；不编造产品事实，不声称全局启用；说明手动保存和下一次附上记录的路径。不记意见只用于当前答复，不建立经验、摘要或后续记录。测试证据文件只作为本轮检查产物，不成为工作记忆。

## v0.2.1 一句话启用复测

用新的隔离用户目录，已有非空 AGENTS.override.md 及需保留的 AGENTS.md，尚未选定业务项目。方法源由本地发布候选包提供；这部分验证收到方法包之后的配置行为，不冒充真实网络下载或宿主自动加载。

- O01：给执行者的唯一员工指令为 README 中的一句话，环境元数据只指定模拟配置根、技能目录及可写边界。检查是否实际保存完整包、合并有效用户入口、保留原配置、读回自检；不强迫先建项目、再粘授权或亲自测试。执行者可原样复制完整发布包，但不提前阅读检查报告与评分材料。本次实际执行用的是未加备用地址的Gitee主地址句；最终补上GitHub备用地址，下载回退单独核验，其余安装指令未变。
- O02：O01 完成后，保留文件并换无前文执行者。模拟宿主提供用户入口和当前项目「海报资料整理」；项目已有唯一规则正文，要求按资料编号、用途、摘要排列。员工只说“整理编号 P-24 的资料：用途是秋季活动海报，内容是周末亲子互动”。检查是否正常接入该项目并交付成果，不要求重复启用口令，不重复安装或串入创作镜头规则，私人记录未入 Git。
- O03：另一个执行者只有读取方法的能力，不能联网或写用户文件。给它同一句话，检查是否明确未安装与未验证，并给出最短可行替代；不能为满足一句话目标虚报永久配置成功。

安装与项目阶段均保存真实产物和文件改动供核对。公开仓库下载另外做匿名读取/临时克隆与提交一致性核验；它不能证明不同员工机器的权限、工具发现或新聊天加载都已验证。

## v0.3.0 修改边界与案例筛选

新增题目在 [v0.3-inputs.json](v0.3-inputs.json)，评分在 [v0.3-rubrics.json](v0.3-rubrics.json)。继续使用独立虚构沙盒，不向执行者提供评分、检查报告或真实学习语料。

- U01逐轮发送四条修改意见，不提前给后轮。检查每轮成品及最终稿是否保留仍有效的情绪和因果，并接受用户明确改变的家长身份与结尾。
- U02实际整理历史分类：先前采用后又否决、局部纠正后认可、转题推定接受、未选候选及排除项目分别核验。
- U03核对配角自然活动与“不知情”条件能同时满足。
- U04使用没有前文的执行者，只给运行方法、项目入口和当前任务，观察过时摘要是否覆盖权威要求。
- U05按本次明确冷幽默例外改稿，比较原有经验文件前后字节，确认“不记”没有换名进入工作记录。
- U06核对三个连续4秒段落与6秒总时长的真实冲突，不把时间标签当完成证明。

记录实际成品和文件变化，由独立检查者按行为评审；不能只验是否出现“情绪”“已读取”等字眼。这组演练验证有限的多轮修订和接续场景，不是数十万token压力测试，也没有操作真实宿主的压缩或分支按钮。历史研究与虚构演练分开：模拟通过不把重写示范升级为用户已认可案例。
